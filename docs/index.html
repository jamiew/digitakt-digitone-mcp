Two machines · two servers

Built for the original Digitakt and Digitone — not the II models. The mk2 machines have different parameter maps, and pointing the wrong map at your hardware puts values in the wrong place, silently.

digitakt-mcp · 44 tools

Digitakt

Eight sample tracks, eight MIDI tracks, one LFO, no chorus.

  • Trigger tracks by number — notes 0–7 handled for you
  • Edit trigs — note, velocity and length per step over NRPN
  • Drive drums and a synth together across channels 1–16
  • Volume CC 7, Pan CC 10 — the mk1 map, not the II's

digitone-mcp · 43 tools

Digitone

Four FM tracks, eight shared voices, two LFOs, chorus on the FX channel.

  • Play chords — tracks are polyphonic, so use the voices
  • Set the algorithm 1–8, get the routing back in words
  • Shape operators — ratios, levels, FM-specific end levels
  • Chorus, delay, reverb on the FX channel

What it can do

Play

Notes, chords, sequences and full patterns locked to real MIDI clock, so the device's own sequencer stays in step with whatever the model plays.

Keep

Save patterns and automation presets as JSON, edit them in place, and export anything to a standard .mid file.

Shape

Named parameters — filter_cutoff, lfo_speed, delay_time — over CC or NRPN, with sweeps and ADSR envelopes.

Listen

Monitor and record incoming MIDI, so a jam on the hardware comes back as a file the model can read.

Add your own machine

A device here is data, not a fork. Describe it once — port name, track count, parameter table — and the shared core gives you every tool.

SPEC = DeviceSpec( slug="syntakt", display_name="Syntakt", port_name="Elektron Syntakt", track_count=12, parameters=parse_parameters(PARAMETER_MAP), register_tools=register_tools, )
